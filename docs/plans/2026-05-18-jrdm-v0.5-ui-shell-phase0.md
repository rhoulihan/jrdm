# JRDM v0.5 UI Shell — Phase 0: Workspace Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`. Steps use checkbox (`- [ ]`) syntax. Design rationale + locked decisions: [`docs/design/2026-05-18-jrdm-ui-redesign.md`](../design/2026-05-18-jrdm-ui-redesign.md) (§9 phases, §10 LOCKED decisions). **Do not relitigate design choices — they are locked.**

**Goal:** Replace the mode-toggle / fixed-sidebar shell with the new workspace skeleton — a menu bar + toolbar, a **draggable vertical SplitPane** with the ERD (left) and the document tree (right) **both always mounted**, a collapsible bottom dock, a slide-over inspector drawer, and a status bar — **with zero feature regression**. Connection/import keeps working (temporarily hosted in a reusable `Modal` off the toolbar; the redesigned ConnectModal flow is Phase 1).

**Architecture:** New `apps/web/src/shell/` module. Leaf feature components (`DiagramPane`, `DocumentTree`, `DdlPane`, `IssuesPanel`, `PreviewPanel`, `ContextInspector`, `ConnectionForm`) are **re-housed, not rewritten**. The `mode`/`setMode` store concept is **removed**; a layout slice is added (`splitRatio`, `dockOpen`, `dockTab`, `inspectorOpen`, `inspectorPinned`, `connectModalOpen`) with `splitRatio`/`dockOpen` persisted to `localStorage` (survive reload; NOT cleared by project `reset()` — layout is a user preference, not project state). Risk concentrates in three new primitives (`SplitPane`, `Modal`, `AppShell`); all are unit-testable in jsdom.

**Tech Stack:** unchanged — React 18, Zustand 5, Tailwind 3, @xyflow/react 12, Vitest+RTL+jsdom, Playwright. **No new deps** (the splitter is hand-rolled — a div + pointer handlers — not a library).

## Conventions (inherited — do not relitigate)

- pnpm + Turbo monorepo. Branch/PR per task. Merge `--squash --delete-branch` ONLY when `lint/typecheck/unit/integration/e2e` all `success`; **`container` is the known non-blocking Trivy carry-forward — its failure does NOT block.** Then `git checkout main && git pull --ff-only`.
- Poll CI to completion yourself (full CI incl. real-Oracle integration runs even for web-only diffs, ~15–25 min): `for i in $(seq 1 120); do S=$(gh run list --branch <branch> --limit 1 --json status,conclusion --jq '.[0]'); echo "[$i] $S"; echo "$S" | grep -q '"status":"completed"' && break; sleep 20; done` then `gh run view <id> --json jobs --jq '.jobs[]|"\(.name): \(.conclusion)"'` then merge. Do NOT stop at "waiting for CI". If `integration` fails ONLY on an Oracle container-startup/hook timeout unrelated to a web-only diff, `gh run rerun <id> --failed` ONCE and re-poll. Never merge red; never `--no-verify`.
- Test-pair gate: every staged `*.ts(x)` source (except `index`) needs a stem-matched colocated test OR a `// @tested-by:` annotation whose named test is co-staged with a genuine new assertion.
- `apps/web` coverage ≥ 70 line / 65 branch. **Production DOM stays clean** (recurring v0.2b/v0.3b lesson): scoped queries (`getByRole`/`getByTestId`/`getByLabelText`/`within`), never fragment/restructure markup to satisfy a query. WCAG: the splitter is a real `role="separator"`, the drawer/modal trap focus and are Esc-dismissable, menus are keyboardable.
- `gh` authed `rhoulihan`, repo `rhoulihan/jrdm`. TDD strictly. **Zero feature regression** is the Phase-0 acceptance bar — every capability reachable today must stay reachable.

## Task P0.T1 — `SplitPane` + `Modal` primitives

**Files:** create `apps/web/src/shell/SplitPane.tsx`(+test), `apps/web/src/shell/Modal.tsx`(+test). Additive only.

- [ ] **Branch** `feat/v05p0-primitives` off fresh `main`.
- [ ] **`SplitPane` — tests first.** Props: `{ left: ReactNode; right: ReactNode; ratio: number; onRatioChange(r:number): void; minRatio?=0.15; collapsed?: "left"|"right"|null; onCollapsedChange(c): void }`. Assert: renders both children; the divider has `role="separator"` `aria-orientation="vertical"` `aria-valuenow={Math.round(ratio*100)}` `tabIndex=0`; pointer drag (pointerdown on divider → pointermove → pointerup, via `fireEvent`/jsdom with a stubbed container `getBoundingClientRect`) calls `onRatioChange` clamped to `[minRatio, 1-minRatio]`; `ArrowLeft`/`ArrowRight` nudge ratio by a step and `Home`/`End` call `onCollapsedChange("left"/"right")` (or ratio 0/1) ; double-click divider → `onRatioChange(0.5)`; collapse chevron buttons (`data-testid="collapse-left"/"collapse-right"`) call `onCollapsedChange`; when `collapsed`, the collapsed side renders a thin rail with a restore control. Scoped queries; no markup contortion.
- [ ] **Implement `SplitPane`** as a flex row: left `flex-basis: ratio*100%`, divider (fixed px, the grab strip + chevrons), right fills remainder; pointer math off the container rect; controlled (parent owns `ratio`/`collapsed`). Pure presentational — no store import.
- [ ] **`Modal` — tests first.** Props `{ open:boolean; title:string; onClose():void; children }`. Assert: nothing rendered when `!open`; when open → `role="dialog"` `aria-modal="true"` `aria-label={title}`, an overlay, a close button (`data-testid="modal-close"`) calling `onClose`, `Escape` key calls `onClose`, focus moves into the dialog on open and is trapped (first/last focusable cycle), overlay click calls `onClose`. Scoped queries.
- [ ] **Implement `Modal`** (portal to `document.body`, focus trap, Esc/overlay close, restores focus to the opener on close). Pure; no store import.
- [ ] `pnpm --filter @jrdm/web test` green; coverage ≥70/65. Commit (each source co-staged with its test). PR `feat/v05p0-primitives`; poll CI; merge per Conventions.

**Self-review:** SplitPane is keyboard+pointer accessible, controlled, clamped, collapsible, no store coupling. Modal traps focus, Esc/overlay close, portal, a11y roles. Both have zero importers yet → main stays green.

## Task P0.T2 — Shell chrome pieces (isolated)

**Files:** create `apps/web/src/shell/{MenuBar,Toolbar,BottomDock,InspectorDrawer,StatusBar}.tsx`(+ colocated tests). Additive only — they take props/callbacks, no store import yet (AppShell wires them in T3), so they're pure and trivially unit-tested and main stays green.

- [ ] **Branch** `feat/v05p0-chrome` off fresh `main` (after T1 merged or in parallel — additive, but sequence after T1 to keep the merge train simple).
- [ ] **Tests-first for each** (props-driven, scoped queries, a11y):
  - `MenuBar({ items })` — renders a `role="menubar"` with top-level `role="menuitem"` buttons (Project/Connection/Deploy/View/Help); opening one shows its `role="menu"` with `menuitem`s that invoke the passed callbacks; ArrowDown/Esc behavior; `data-testid="menubar"`.
  - `Toolbar({ connection, onConnect, onImport, onDeploy, onResetSplit, onFit })` — a connection **status chip** (`data-testid="conn-status"`, class/aria reflects `"disconnected"|"connected"|"error"`), buttons `connect-btn`/`import-btn`/`deploy-btn` calling their callbacks, canvas/split controls; `data-testid="toolbar"`.
  - `BottomDock({ open, tab, onToggle, onTab, tabs })` — collapsed → only a thin strip with tab labels + an expand affordance (`data-testid="dock-expand"`); open → renders the active tab's content (`tabs` is `{id,label,node}[]`); `role="tablist"`/`tab`/`tabpanel`; `data-testid="bottom-dock"`.
  - `InspectorDrawer({ open, pinned, onClose, onTogglePin, children })` — when `open` slides in (`data-testid="inspector-drawer"`), close button + pin toggle; not in DOM (or `aria-hidden`) when closed and unpinned; Esc closes when not pinned.
  - `StatusBar({ project, view, erdZoom, docZoom, valid })` — renders the status text + a `data-testid="status-bar"`.
- [ ] Implement each minimally to satisfy the tests; Tailwind per the locked tokens (accent `#C74634` etc.); all presentational/controlled.
- [ ] `pnpm --filter @jrdm/web test` green; coverage ≥70/65. Commit; PR `feat/v05p0-chrome`; poll; merge.

**Self-review:** every chrome piece is pure/controlled, a11y-correct, has zero store coupling and zero importers yet → main green; ready for AppShell to wire.
